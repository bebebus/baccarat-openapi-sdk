# B2B Operator Seamless Wallet Endpoints & Status Codes (v1.6.0)

Interactive Explorer & OpenAPI 3.1 Spec: `https://openapi.lt.cniia.cloud`

## 1. Inbound S2S Endpoints (Merchant -> Platform)

All endpoints accept `POST` JSON signed with `X-API-Key` and `X-Signature` (plus optional `X-Timestamp` anti-replay within `±300s`), returning `{ traceId, status: "SC_OK", data }` on `HTTP 200` or `{ traceId, status: "SC_*", message, validation? }` on error (`HTTP 200` by default — in `v1.6.0+`, `/operator/v1/*` `body-parser` malformed JSON / `> 100 KB` / unsupported encoding errors also normalize to `HTTP 200` `SC_INVALID_REQUEST`; `POST /operator/v1/player/status` additionally returns structured JSON error envelopes with `HTTP 403` `SC_USER_DISABLED` / `PLATFORM_RISK_LOCKED`, `HTTP 409` `SC_INVALID_REQUEST` / `PNL_CAP_BREACHED_RESET_REQUIRED`, or `HTTP 400` `SC_INVALID_REQUEST`, all parsed into typed API errors across all 7 SDKs):

1. **`POST /operator/v1/ping`** (`ping` / `ping` / `Ping`): Authenticated credential & IP allowlist self-test (`operatorId, operatorName, callerIp, callbackConfigured, serverTime`).
2. **`POST /operator/v1/game/tables`** (`listTables` / `list_tables` / `ListTables`): Lists permitted live tables with operating `currency`, dynamic `minBet`/`maxBet`/`chipUnit`, `status`, and `coverImageUrl`.
3. **`POST /operator/v1/game/url`** (`createGameUrl` / `create_game_url` / `CreateGameUrl`): Issues a single-use launch URL (`gameUrl`) and 53-char `b2bt_<48hex>` wallet token (`entryMode`: `lobby | table | table_locked`).
4. **`POST /operator/v1/game/terminate`** (`terminateSessions` / `terminate_sessions` / `TerminateSessions`): Revokes active sessions and unused launch tokens (`scope`: `USER | ALL`).
5. **`POST /operator/v1/player/status`** (`updatePlayerStatus` / `update_player_status` / `UpdatePlayerStatus`): Queries (`GET`) or updates (`SET`) `ACTIVE | DISABLED` login status, view-only `bettingEnabled` switch, and atomic `resetPnlWindow: true` PnL auto-stop reset (`revokedSessions`, `rgRestricted`, `statusReason`; HTTP `403` on platform risk lock, HTTP `409` when `resetPnlWindow: true` is required).
6. **`POST /operator/v1/player/limits`** (`updatePlayerLimits` / `update_player_limits` / `UpdatePlayerLimits`): Queries (`GET`), sets (`SET`), or clears (`CLEAR`) per-player dynamic bet/loss limits & chips bounded beneath the operator risk template.
7. **`POST /operator/v1/player/balance-notify`** (`notifyPlayerBalance` / `notify_player_balance` / `NotifyPlayerBalance`): Pushes a lightweight money-free WS `balance_changed` signal to online player sessions after main-site deposit/bonus/adjustment (optional `currency` & server-side-only `reason <= 64` chars; returns `{ username, currency, notified, activeSessions, serverTime }`; default rate limit `600 req / 60s`).
8. **`POST /operator/v1/game/ccu`** (`getGameCcu` / `get_game_ccu` / `GetGameCcu`): Queries multi-pod deduplicated operator CCU (`onlinePlayers`, `seatedPlayers`, `lobbyPlayers`, `tables[{ tableId, gameCode, playerCount }]`, `serverTime`; optional `tableId` filter; rate limit `120 req / 60s`).
9. **`POST /operator/v1/transaction/list`** (`listTransactions` / `list_transactions` / `ListTransactions` + `listAllTransactions` auto-paginator with `SC_RATE_LIMITED` backoff; for optional filters & custom retry backoff use `ListAllTransactionsWithOptions` in Go and `list_all_transactions_with_options` in Rust): Paginated settled & voided ticket feed (`SETTLE_TIME` or `BET_TIME`; `fromTime`/`toTime` non-nullable integer epoch ms; rate limit `120 req / 60s` sliding window; `VOID` rows have `vendorSettleTime: null`).
10. **`POST /operator/v1/transaction/detail`** (`getTransactionDetail` / `get_transaction_detail` / `GetTransactionDetail`): Single-ticket lookup (omit both `fromTime`/`toTime` for trailing 7 days; explicit `null` rejected; supports `language` and `detailUrlTtlSec`) with revealed cards (`BaccaratRevealedCard.suit` numeric `1..4`: `1=♠, 2=♥, 3=♦, 4=♣`), `detailUrl`, and `adjustments[]`.
11. **`POST /operator/v1/transaction/unsettled`** (`listUnsettledTransactions` / `list_unsettled_transactions` / `ListUnsettledTransactions`): Open `ACCEPTED` / `HELD` exposure feed (`fromTime`/`toTime` non-nullable integers; rate limit `120 req / 60s` sliding window).
12. **`POST /operator/v1/wallet/transaction-status`** (`getWalletTransactionStatus` / `get_wallet_transaction_status` / `GetWalletTransactionStatus`): Paginated real-time outbound callback delivery & retry inspection by `transactionId`, `betId`, or `username` (with `<= 24h` non-nullable `[fromTime, toTime]` window). Ordered by `createdAt ASC, id ASC` with optional `pageNo` (`1..1000000`, default `1`) and `pageSize` (`1..200`, default `200`), returning `transactions[]`, `pageNo`, `pageSize`, `total`, and `hasMore`.

## 2. Outbound Seamless Wallet Webhooks (Platform -> Merchant `{callbackUrl}/wallet/*`)

Every SDK ships a framework-agnostic `WebhookDispatcher` and `InMemoryWallet` reference store handling:

1. **`POST /wallet/balance`** — Read-only balance check (`SC_OK` + `data.balance`).
2. **`POST /wallet/bet`** — Idempotent stake deduction by `transactionId = bet_<32hex>`.
3. **`POST /wallet/bet_result`** — Per-ticket settlement by `transactionId = stl_<32hex>` (`WIN` = stake + netPayout; Tie `PUSH` also sends `resultType = "WIN"` with `winAmount = betAmount`, `winLoss = "0.00"` or `"0"` for 0-decimal currencies like `JPY`, `effectiveTurnover = "0.00"` / `"0"`; `LOSE` = `"0.00"` / `"0"` — **never compare zero with `=== "0.00"`**; in `v1.6.0+` multi-bet rounds are delivered serially per player on the happy path with **`isEndRound: 1` ONLY on the last non-`REJECTED` ticket** and `0` on earlier tickets across initial delivery and retries; honor settled tickets even if player session expired).
4. **`POST /wallet/rollback`** — Void/late-close refund by `transactionId = rb_<betId>` or `late_<betTxId>` (returns `SC_TRANSACTION_NOT_EXISTS` empty-success when original `betId` was never debited).
5. **`POST /wallet/adjustment`** — Post-settlement recalculation or appeal delta adjustment by `transactionId = adj_<ref>` (`CREDIT` or `DEBIT`; returns `SC_INSUFFICIENT_FUNDS` on `DEBIT` shortfall without infinite retries).

> **4 Critical Production Webhook Invariants**:
> 1. **Per-player serial happy-path settlement + 4-way cross-player concurrency (row locks still required)**: In `v1.6.0+`, same-round `/wallet/bet_result` deliveries for one player are serialized by `(createdAt ASC, id ASC)` on the happy path while keeping up to 4 concurrent callbacks per operator across distinct players. Because transient retries on an earlier ticket do not block later tickets, still guard balance updates with per-player DB row locks (`SELECT ... FOR UPDATE`) or atomic `UPDATE ... SET balance = balance + delta` plus `UNIQUE(transaction_id)`.
> 2. **Deterministic `isEndRound` (`v1.6.0+`)**: In multi-bet rounds, `isEndRound: 1` is sent ONLY on the player's last non-`REJECTED` ticket (`0` on earlier tickets), deterministically preserved across initial delivery and retries/redrives; still settle strictly per `betId` / `transactionId` in case retries reorder deliveries.
> 3. **Terminal HTTP/JSON traps & `~5.07h` retry horizon (1 initial + 12 auto-retries)**: Returning `HTTP 200` with a non-JSON body, or a non-2xx JSON response without a transient `SC_*` status, immediately parks `/wallet/bet_result` winning tickets in `HELD` with **0 retries**. All 7 SDK `WebhookDispatcher` implementations automatically convert unexpected runtime/DB exceptions (e.g. Postgres `40P01` deadlocks) into retryable `SC_OPERATOR_TIMEOUT` with a sanitized message.
> 4. **0-decimal currencies format zero as `"0"` & outbound `X-Timestamp`**: Currencies such as `JPY`, `KRW`, and `VND` emit `"0"` instead of `"0.00"` (never use `=== "0.00"`). All 5 outbound `/wallet/*` webhooks carry a 13-digit ms `X-Timestamp` header (NOT included in `X-Signature`).

## 3. Retryability Rule

Among all 18 `SC_*` status codes, **`SC_TRANSACTION_STILL_PROCESSING`**, **`SC_OPERATOR_TIMEOUT`**, and **`SC_RATE_LIMITED`** are transient/retryable (`isRetryable === true`), and wallet callbacks MUST be retried with the **exact same `transactionId`**. On outbound settlement/rollback/adjustment webhooks, `SC_UNDER_MAINTENANCE` is also retried automatically by the platform up to 12 attempts before dead-lettering.
